# Shift Plan (SSS)

Support-floor coverage calendar. One HTML file. The live page is https://osaid-ak.github.io/sss/ and the header reads **Shift Plan**.

Read this file before changing the calendar. Update it in the same change when behavior, publish steps, or standing rules change.

## Files

- `coverage-calendar.html` is the working copy. It is not committed.
- `index.html` is the published page. It must match the working copy before a commit.
- `serve-calendar.py` is a local server only. Do not commit it.
- `README.md` is the short tester note. Keep it consistent with this file.

## Publish

1. Edit `coverage-calendar.html`.
2. Copy it over `index.html`.
3. Commit only `index.html` for calendar changes, plus this file when the rules changed.
4. Push `main`. GitHub Pages serves `/` from `main`.
5. Tell the user to hard-refresh with Ctrl+F5. Pages can keep the previous HTML while a build is running.

Do not commit `coverage-calendar.html`, `serve-calendar.py`, or secrets. On PowerShell, commit with `git commit -m "..."` and chain commands with `;`.

## Sign-in gate (Cloudflare Worker, in `worker/`)

Access is restricted to people on the allowed email list, who sign in with Google (Intercom sign-in was dropped: it is an app-install flow that regular teammates cannot authorize). The worker serves the calendar page and proxies the shared plan; nothing is served before sign-in. Secrets (Google client ID and secret, session secret, plan address, allowed emails, admin emails, Super Admin email) are Cloudflare secrets, never in the repo or in chat. `worker/README.md` has the setup. `worker/deploy.ps1` builds `worker/public/index.html` from `coverage-calendar.html` (swapping the plan address for `/api/team/plan` and setting `SSS_GATED = true`) and deploys; `worker/public/` is not committed. Run `node worker/test.mjs` after changing the worker.

Roles when gated: Member (no Access button, no lead tools), Admin (lead access without the PIN, plus Users under Access to add people as Members, remove Members and change Members' roles; added and removed people are kept in the ROLES store on top of `ALLOWED_EMAILS`) and Super Admin (one person; the only one who can add an Admin or change or remove an Admin). Everyone signed in gets a Sign out button in the header. Sessions are signed cookies (7 days), not a server-side list; the worker keeps an activity log of the latest 500 events (sign-in, refused sign-in, sign-out, user added, removed or role changed) in the ROLES store, readable by Admins under Access > Activity log. Each entry holds email, event, time, country, IP address and browser (User-Agent, shortened to 200 characters); these are personal data of teammates, so only Admins can read them and they are never shown to Members. The log has a search box that filters live from 2 characters on (several words must all match) across everything shown in a row: time, event, email, detail, IP, browser, country. The panel shows a short label such as "Chrome on Windows" with the full browser string on hover. The IP and browser fields are there so a future mobile app's sign-ins can be told apart. The server decides the role (`/api/me`) and enforces role changes. `SSS_GATED` stays `false` in the committed file; the PIN flow still applies to the ungated GitHub Pages copy.

Status: the code is written and tested offline, but until the worker is deployed and the public copy is closed (see "Closing the public copy" in the worker README), the GitHub Pages page and the old plan address are still public and the Publish steps below still apply. Once the gate is live, publishing a calendar change means running `worker/deploy.ps1`, and `index.html` becomes the redirect stub. Update this file when that happens.

## How the data is shared

Edits sync through the shared plan named `TEAM_PLAN` in the calendar file. A browser also keeps a local copy. Do not describe the calendar as Export/Import only.

Safety rule: a browser that has no plan of its own must adopt the team plan exactly on first contact, and data read from the Google Sheet (weekend names, VIP blocks) is saved quietly without counting as a team edit. Never let anything bump `updatedAt` or push before the first team sync finishes, because built-in default names and hours would then overwrite the team's roster. When testing, never load the live page from a fresh browser such as the preview pane. Use a copy pointed at a local stand-in for the team plan.

Each browser keeps up to 5 automatic backups (local storage key `coverage-calendar-backups`), taken before a teammate or merged update (at most every 15 minutes) and before a JSON import or restore. Lead tools has Restore backup. Import asks for confirmation because it replaces the shared plan. Browser panes that block storage skip backups silently.

Always read the Actual Cover columns on the sheet, not Planned. Actual updates itself when a swap happens. Swap, then Planned, only fill in when Actual is blank. Saturday names come from the Weekend Cover sheet. The sheet has no time columns. The product windows are Phase 1 8pm–2am and VIP 5pm–2am. Display re-applies those windows, then adds one hour on standard-time dates. Do not make that spreadsheet world-editable. Do not rewrite stored clocks unless the user asks.

The `2. VIP Coverage Plan` tab (gid 1563923804, same workbook) lists two-week Monday to Friday blocks. Each block names one VIP person on Late Shift and one on Phase 1, read from Actual Cover, plus the two anchor cover names from the Anchor 1 and Anchor 2 columns. The page polls it with the weekend sheet and stores the blocks in the shared plan as `vipPlan`. On weekdays inside a block, the Late Shift person works 9:30pm–6:30am PKT (10:30pm–7:30am on standard-time dates), keeping their usual break offset, and the Phase 1 person moves from VIP to Phase 1 for the whole shift. Days someone edited by hand keep their own edit. Saturdays and Sundays are not affected. A failed read keeps the last blocks.

Every weekday late shift (anyone starting at 9:30pm PKT, or 10:30pm on standard-time dates, or later) needs one working VIP person and one working Phase 1 person. People who are Off or PTO do not count. When one is missing, the day view shows a red alert above the timeline naming who is off, and the month and week cells for that day show the red gap tint. With lead access the alert has a dropdown and Add cover button. Phase 1 queue cover is separate from the late shift: if the Phase 1 person the VIP Coverage Plan names is off, the day shows a Phase 1 needs cover alert and the Lead action highlight until a lead adds a VIP rep to Phase 1 (stored as `p1q` in `lateCover`; the rep keeps their own hours and only moves to the Phase 1 queue). It does not touch the late-shift rule, and days a lead edited by hand are not flagged. Leads (anyone with the Lead role) are never offered as cover. Nobody already used as cover on that night or in that block (late, Phase 1 queue or anchor) is offered again, so one person never gets two jobs. Cover dropdowns only list reps of the matching queue for that day: VIP cover lists VIP reps, Phase 1 cover lists Phase 1 reps, anchor shift cover (a VIP seat, for both the Late Shift and the Phase 1 gap) lists VIP reps, and the Phase 1 queue cover (a VIP rep moving to Phase 1) lists VIP reps. A VIP rep who is the block's Phase 1 person counts as a Phase 1 rep for those two weeks (and is not offered for VIP cover), and goes back to VIP when the block ends. The chosen person takes the late hours and the queue that is missing for that night, and a lead can Remove it. Covers are stored per date in the shared plan as `lateCover` and merge per date. Only people with lead access (Admins when gated, or the PIN on the ungated copy) see the red alerts, the dropdowns, the Lead action badges and outlines, and the needs-action chip; Members cannot act on them, so they see none of it. In the week and month views a night that still needs a lead (late shift missing a VIP or Phase 1 person, or a Support Line owner off with no backup cover) gets a red outline, a tint and a Lead action badge on the whole card, whatever filters are on. The badge tooltip says why. Nights that have passed are not flagged, and the highlight clears once cover is added.

The Phase 1 / Support Line tab (gid 274979110, same workbook) is treated as always accurate. It has two parts, both read with the other sheets and saved quietly as `sheetPlan`. First, the four-week Support Line rotation: each block lists who covers the three line slots in order (6–10pm, 10pm–1am, 1–4am in standard time, which is 5–9pm, 9pm–12am, 12–3am on the summer schedule) plus a backup. On weekdays inside a block the rotation replaces the line bars; the slot times are fixed in the page, only the names come from the sheet. Second, the table at the top with current shift hours and breaks for the people listed (Qasim, Ayeshah, Schanzae, Ivan at the time of writing); those override the roster for those people on every date. The tab's clock is that of the current season, so the page takes the standard-time hour back off using today's date. Days someone edited by hand keep their own edit. When a line slot owner is off, the sheet's backup takes that slot automatically, and if the slot is already inside their shift only the Support Line bar is added and the shift is left alone. Only when it is not inside does the whole shift move (same length, same break position) to cover it. One backup can only take the slots that fit into a single shift, earliest first, and the rest show a red alert. Anyone who is covering shows "(covering)" in brackets after their name everywhere they appear (day view bars and Support Line bars, week lists, month lists), with the detail on hover, and the day view has a "Covering tonight" box at the top for everyone listing who is covering whom and what, for example "Qasim is covering Laraib on Support Line 6pm–10pm. Qasim's shift was adjusted to 6pm–3am to cover the Support Line." This covers the Support Line backup (also on hand-edited days, and when a lead placed a bar over an absent owner's slot), late-shift cover, the Phase 1 queue cover and anchor-shift cover, and it applies to Members too. Only when there is no backup, or the backup is off too, does a red alert appear and the Gaps row show the hole. A failed read keeps the last copy, including when only the rotation dates cannot be read (the date cells have appeared as both "Oct 5, 2026" and "Oct 5, 26"; both are accepted). Dates on all sheet tabs go through one reader (`parseAnyDate`) that accepts month-name, day-first, ISO, slash and dot forms with 2- or 4-digit years, and date-only cells are read from their real value, not their display text. Slash dates are read month first unless the first number is over 12. People missing from the roster are skipped. Check that this tab still matches when the clocks change in March.

Anchor shifts: the VIP sheet names three shifts that must always be held: 5PM–2AM, 6PM–3AM and 8PM–5AM on its current (standard-time) clock. They are the three single-person shifts (Osaid, Raza, Jawad), which the page stores as summer-schedule slots 2, 4 and 8, so it follows DST by itself (the sheet's own anchor text is fixed and needs checking in March, like the Support Line tab). When a block's Late Shift person or Phase 1 person normally works one of them (their roster or sheet shift, before the block changes anything), that anchor is vacated for the block. Anchor Cover 1 (column K of the VIP Coverage Plan tab) covers the Late Shift person's gap and Anchor Cover 2 (column L) covers the Phase 1 person's gap; the team fills them in on the sheet, and the page only reads them (stored per block in `vipPlan` as `cover1` and `cover2`). There is no anchor cover picker in the page. The cover person takes the vacated anchor's hours, with the VIP queue, on every weekday of the block; the Phase 1 person keeps their own hours. Until the cell is filled, leads see a red "Anchor shift … is uncovered" alert with an Open the sheet button (it opens the Shift Sheet on the VIP Coverage Plan tab) and the Lead action highlight; once filled, everyone sees "(covering)" tags and the Covering tonight box. This matches the sheet's own column J warning (checked against it). Days a lead edited by hand are not touched.

Sheet-read data (`vipPlan`, `sheetPlan`) carries a `readAt` stamp set only when its content changes, and the shared plan keeps whichever copy has the newer `readAt` instead of using the plan's edit time, so a stale copy can never put back an older version of the sheet.

## Standing rules

- Primary time is PKT. ET is the secondary label. Overnight hours stay on the start day. Sunday is closed.
- Sundays stay hidden until someone clicks Show Sundays. Show them only when local storage `coverage-calendar-show-closed` is `"1"`.
- Default role filters are Phase 1, VIP, and Support Line. Lead is off. Clear restores those three, not an empty set.
- Away is a separate multi-select for Off and PTO. Nothing is selected by default, so everyone shows. Select all checks both and shows only those people. Off is the holiday rotation. PTO is holiday PTO or approved leave.
- Names in a month cell are listed by shift start time, earliest first, then by name. People who are Off or PTO stay visible, red with a strikethrough (white in Night, black in Frost), at the end of the time group. The count on a time chip does not include them.
- Week columns show shift times as chips: time on the left, working headcount on the right. Support Line is a separate section at the bottom of each weekday, grouped by start time only. Saturday has no Support Line section.
- The day view is one timeline list, grouped Leads, then VIP, then Phase 1. Do not put Phase 1 and VIP side by side unless the user asks again. The day view has no header block (no Back button, title, subtitle or peak chips) because the top bar already shows the date and view switch. Rows are compact so the day fits with little scrolling. Today's night shows a red Now line with a PKT time pill (real PKT clock, refreshed every 30 seconds), and the timeline scrolls sideways to it on narrow screens. A Gaps row under the peak band flags slots inside the peak window (Phase 1, VIP) and the Support Line window with 0 people (red) or 1 person (amber); it follows DST and is hidden on Saturdays and Sundays. Only a Saturday cover note and the edit-mode Reset button appear above the timeline.
- Year is hidden until lead access is unlocked, and it hides again when access is locked.
- Print and Export sit under Access. The header has one Shift Sheet button that opens the whole Google Sheet workbook inside the calendar, starting on the Weekend Cover tab. Users switch tabs inside the sheet. It is an embedded editor, so edit rights follow the viewer's Google account, and an Open in Google Sheets link is the fallback. Back to calendar, Escape, or changing view closes it and re-reads the sheet; while open it re-reads every 20 seconds. There is no Sync sheet button: all sheet tabs are re-read automatically.
- DST is automatic and follows US Eastern time, because shifts are anchored to ET. Stored clocks are the summer (EDT) schedule. From the first Sunday of November to the second Sunday of March, every date shows its shifts, breaks, splits, line assignments and Saturday windows one hour later in PKT, and the Peak window (7pm–12am becomes 8pm–1am) and Support Line window (5pm–3am becomes 6pm–4am) move with them. The board itself stays 3pm–8am PKT. There is no DST button, and `dst` in saved data is always false. Older plans saved with the global switch on are converted back to the summer schedule on load. Per-day edits are stored as shown for that day. Do not reintroduce a manual switch unless asked.
- The lead PIN is in the page source. Do not print it in chat or in the UI.

- UI regression check: every change that adds or alters something visible must be looked at on screen before it is published, not only syntax-checked. Check a desktop width and a phone width (375px), the Night and Frost themes, and long content (for example the user list with 15+ people, a day with many names). Panels that can grow (Users, Activity log, modals) keep their header and buttons fixed and scroll only the list, and must fit inside the window. Do this alongside the data checks, every time.
- Month health markers: every upcoming weekday and covered Saturday cell has a small marker next to the date: a tick (covered all night), "!" (only one person on Phase 1 or VIP for part of the peak window) or a cross (nobody in part of the peak window, the Support Line window, or, for leads, a late shift missing a VIP or Phase 1 person). The shape carries the meaning as well as the colour, hovering gives the reason, and a legend sits under the grid. The Support Line is one person per slot by design, so only an empty slot counts there. Past nights, closed days and Saturdays still waiting for Actual Cover get no marker. Everyone sees them.
- Interface rules: for leads only, the header shows a red "N nights need action" chip (just "! N" on phones) that opens a list of the next four weeks' nights that need a lead, each opening that day. When gated, the Theme button becomes an account button (initials) whose menu shows the email and role, the theme choice and Sign out. Messages use non-blocking toasts, not browser alerts; cover changes show an Undo toast; confirmations use the in-page dialog (`askConfirm`), except the unsaved-changes prompt, which stays native because it runs in synchronous close paths. A browser with no plan of its own shows "Loading the team plan…" (or a Try again card if it fails) instead of the built-in starter data, and never edits until the first team sync finishes. The first visit follows the device's light or dark setting. Keep every text colour at 4.5:1 contrast or better in both themes (Frost values were darkened for this) and keep the visible keyboard focus outline. Dialogs have `role="dialog"`, and Escape closes them. On phones, month and day views swipe left or right to change month or day (week view and the day timeline scroll sideways instead), and buttons are at least 38 to 40px tall.
- Calendar text (month, week, day and timeline) is one pixel larger than the original sizes, with the same layout. Keep that scale when adding new text.

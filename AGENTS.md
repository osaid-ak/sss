# Shift Plan (SSS)

Support-floor coverage calendar. One HTML file. The live page is https://osaid-ak.github.io/sss/ and the header reads **Shift Plan**.

Read this file before changing the calendar. Update it in the same change when behavior, publish steps, or standing rules change.

## Files

- `coverage-calendar.html` is the working copy. It is not committed.
- `index.html` is the published page. It must match the working copy before a commit.
- `serve-calendar.py` is a local server only. Do not commit it.
- `README.md` is the short tester note. Keep it consistent with this file.

## Publish

1. Edit `coverage-calendar.html`.
2. Copy it over `index.html`.
3. Commit only `index.html` for calendar changes, plus this file when the rules changed.
4. Push `main`. GitHub Pages serves `/` from `main`.
5. Tell the user to hard-refresh with Ctrl+F5. Pages can keep the previous HTML while a build is running.

Do not commit `coverage-calendar.html`, `serve-calendar.py`, or secrets. On PowerShell, commit with `git commit -m "..."` and chain commands with `;`.

## Sign-in gate (Cloudflare Worker, in `worker/`)

Access is restricted to Intercom teammates whose email is on the allowed list. The worker serves the calendar page and proxies the shared plan; nothing is served before an Intercom OAuth sign-in. The allowed list, Intercom client ID and secret, session secret and plan address are Cloudflare secrets, never in the repo or in chat. `worker/README.md` has the setup and how to change the list. `worker/deploy.ps1` builds `worker/public/index.html` from `coverage-calendar.html` (swapping the plan address for `/api/team/plan`) and deploys; `worker/public/` is not committed. Run `node worker/test.mjs` after changing the worker.

Status: the code is written and tested offline, but until the worker is deployed and the public copy is closed (see "Closing the public copy" in the worker README), the GitHub Pages page and the old plan address are still public and the Publish steps below still apply. Once the gate is live, publishing a calendar change means running `worker/deploy.ps1`, and `index.html` becomes the redirect stub. Update this file when that happens.

## How the data is shared

Edits sync through the shared plan named `TEAM_PLAN` in the calendar file. A browser also keeps a local copy. Do not describe the calendar as Export/Import only.

Safety rule: a browser that has no plan of its own must adopt the team plan exactly on first contact, and data read from the Google Sheet (weekend names, VIP blocks) is saved quietly without counting as a team edit. Never let anything bump `updatedAt` or push before the first team sync finishes, because built-in default names and hours would then overwrite the team's roster. When testing, never load the live page from a fresh browser such as the preview pane. Use a copy pointed at a local stand-in for the team plan.

Each browser keeps up to 5 automatic backups (local storage key `coverage-calendar-backups`), taken before a teammate or merged update (at most every 15 minutes) and before a JSON import or restore. Lead tools has Restore backup. Import asks for confirmation because it replaces the shared plan. Browser panes that block storage skip backups silently.

Always read the Actual Cover columns on the sheet, not Planned. Actual updates itself when a swap happens. Swap, then Planned, only fill in when Actual is blank. Saturday names come from the Weekend Cover sheet. The sheet has no time columns. The product windows are Phase 1 8pm–2am and VIP 5pm–2am. Display re-applies those windows, then adds one hour on standard-time dates. Do not make that spreadsheet world-editable. Do not rewrite stored clocks unless the user asks.

The `2. VIP Coverage Plan` tab (gid 1563923804, same workbook) lists two-week Monday to Friday blocks. Each block names one VIP person on Late Shift and one on Phase 1, read from Actual Cover. The page polls it with the weekend sheet and stores the blocks in the shared plan as `vipPlan`. On weekdays inside a block, the Late Shift person works 9:30pm–6:30am PKT (10:30pm–7:30am on standard-time dates), keeping their usual break offset, and the Phase 1 person moves from VIP to Phase 1 for the whole shift. Days someone edited by hand keep their own edit. Saturdays and Sundays are not affected. A failed read keeps the last blocks.

Every weekday late shift (anyone starting at 9:30pm PKT, or 10:30pm on standard-time dates, or later) needs one working VIP person and one working Phase 1 person. People who are Off or PTO do not count. When one is missing, the day view shows a red alert above the timeline naming who is off, and the month and week cells for that day show the red gap tint. With lead access the alert has a dropdown and Add cover button. Phase 1 queue cover is separate from the late shift: if the Phase 1 person the VIP Coverage Plan names is off, the day shows a Phase 1 needs cover alert and the Lead action highlight until a lead adds a VIP rep to Phase 1 (stored as `p1q` in `lateCover`; the rep keeps their own hours and only moves to the Phase 1 queue). It does not touch the late-shift rule, and days a lead edited by hand are not flagged. Leads (anyone with the Lead role) are never offered as cover. Cover dropdowns only list reps of the matching queue for that day: VIP cover lists VIP reps, Phase 1 cover lists Phase 1 reps, anchor shift cover (a VIP seat, for both the Late Shift and the Phase 1 gap) lists VIP reps, and the Phase 1 queue cover (a VIP rep moving to Phase 1) lists VIP reps. A VIP rep who is the block's Phase 1 person counts as a Phase 1 rep for those two weeks (and is not offered for VIP cover), and goes back to VIP when the block ends. The chosen person takes the late hours and the queue that is missing for that night, and a lead can Remove it. Covers are stored per date in the shared plan as `lateCover` and merge per date. Without lead access the alert says a lead can add cover from Access. In the week and month views a night that still needs a lead (late shift missing a VIP or Phase 1 person, or a Support Line owner off with no backup cover) gets a red outline, a tint and a Lead action badge on the whole card, whatever filters are on. The badge tooltip says why. Nights that have passed are not flagged, and the highlight clears once cover is added.

The Phase 1 / Support Line tab (gid 274979110, same workbook) is treated as always accurate. It has two parts, both read with the other sheets and saved quietly as `sheetPlan`. First, the four-week Support Line rotation: each block lists who covers the three line slots in order (6–10pm, 10pm–1am, 1–4am in standard time, which is 5–9pm, 9pm–12am, 12–3am on the summer schedule) plus a backup. On weekdays inside a block the rotation replaces the line bars; the slot times are fixed in the page, only the names come from the sheet. Second, the table at the top with current shift hours and breaks for the people listed (Qasim, Ayeshah, Schanzae, Ivan at the time of writing); those override the roster for those people on every date. The tab's clock is that of the current season, so the page takes the standard-time hour back off using today's date. Days someone edited by hand keep their own edit. When a line slot owner is off, the sheet's backup takes that slot automatically, and if the slot is already inside their shift only the Support Line bar is added and the shift is left alone. Only when it is not inside does the whole shift move (same length, same break position) to cover it. One backup can only take the slots that fit into a single shift, earliest first, and the rest show a red alert. The backup is labeled "(backup)" on the Support Line bar in the day view and in the week Support Line list. This also applies on days a lead edited by hand, whenever the sheet's backup holds a bar over an absent owner's slot. The day view shows a plain grey update, not a red alert, for example "Laraib is off. Qasim replaced the 6pm–10pm Support Line slot. Qasim's shift was adjusted to 6pm–3am to cover the Support Line." If a lead already placed someone's Support Line bar over the slot by hand, the day view shows a grey note naming who covers it, not a red alert. Only when there is no backup, or the backup is off too, does a red alert appear and the Gaps row show the hole. A failed read keeps the last copy, including when only the rotation dates cannot be read (the date cells have appeared as both "Oct 5, 2026" and "Oct 5, 26"; both are accepted). Dates on all sheet tabs go through one reader (`parseAnyDate`) that accepts month-name, day-first, ISO, slash and dot forms with 2- or 4-digit years, and date-only cells are read from their real value, not their display text. Slash dates are read month first unless the first number is over 12. People missing from the roster are skipped. Check that this tab still matches when the clocks change in March.

Anchor shifts: 5pm–2am, 6pm–3am and 8pm–5am (summer clocks, one hour later on standard-time dates) must always be held. Logic taken from the team's VIP sheet. When the block's Late Shift person or Phase 1 person normally works one of them (their roster or sheet shift, before the block changes anything), that anchor is vacated for the block, unless another VIP-role, non-lead person has the same shift (Phase 1 people on the same hours do not hold it). The day view shows a red "Anchor shift … is uncovered" alert, and the week and month cards get the Lead action highlight, until a lead picks a replacement for that duty (one for the Late Shift gap, one for the Phase 1 gap; the dropdown excludes leads, both duty people and the other replacement). The replacement is stored once per block as `anchorCover` (keyed by the block's first date, merged like `lateCover`) and takes the vacated anchor's hours, with the VIP queue, on every weekday of the block. A covered gap shows a plain line with Remove. Days a lead edited by hand are not touched. The Phase 1 person keeps their own hours; only the vacated anchor needs a replacement.

## Standing rules

- Primary time is PKT. ET is the secondary label. Overnight hours stay on the start day. Sunday is closed.
- Sundays stay hidden until someone clicks Show Sundays. Show them only when local storage `coverage-calendar-show-closed` is `"1"`.
- Default role filters are Phase 1, VIP, and Support Line. Lead is off. Clear restores those three, not an empty set.
- Away is a separate multi-select for Off and PTO. Nothing is selected by default, so everyone shows. Select all checks both and shows only those people. Off is the holiday rotation. PTO is holiday PTO or approved leave.
- Names in a month cell are listed by shift start time, earliest first, then by name. People who are Off or PTO stay visible, red with a strikethrough (white in Night, black in Frost), at the end of the time group. The count on a time chip does not include them.
- Week columns show shift times as chips: time on the left, working headcount on the right. Support Line is a separate section at the bottom of each weekday, grouped by start time only. Saturday has no Support Line section.
- The day view is one timeline list, grouped Leads, then VIP, then Phase 1. Do not put Phase 1 and VIP side by side unless the user asks again. The day view has no header block (no Back button, title, subtitle or peak chips) because the top bar already shows the date and view switch. Rows are compact so the day fits with little scrolling. Today's night shows a red Now line with a PKT time pill (real PKT clock, refreshed every 30 seconds), and the timeline scrolls sideways to it on narrow screens. A Gaps row under the peak band flags slots inside the peak window (Phase 1, VIP) and the Support Line window with 0 people (red) or 1 person (amber); it follows DST and is hidden on Saturdays and Sundays. Only a Saturday cover note and the edit-mode Reset button appear above the timeline.
- Year is hidden until lead access is unlocked, and it hides again when access is locked.
- Print and Export sit under Access. The header has one Shift Sheet button that opens the whole Google Sheet workbook inside the calendar, starting on the Weekend Cover tab. Users switch tabs inside the sheet. It is an embedded editor, so edit rights follow the viewer's Google account, and an Open in Google Sheets link is the fallback. Back to calendar, Escape, or changing view closes it and re-reads the sheet; while open it re-reads every 20 seconds. Sync sheet (weekend and VIP plan) stays in the header.
- DST is automatic and follows US Eastern time, because shifts are anchored to ET. Stored clocks are the summer (EDT) schedule. From the first Sunday of November to the second Sunday of March, every date shows its shifts, breaks, splits, line assignments and Saturday windows one hour later in PKT, and the Peak window (7pm–12am becomes 8pm–1am) and Support Line window (5pm–3am becomes 6pm–4am) move with them. The board itself stays 3pm–8am PKT. There is no DST button, and `dst` in saved data is always false. Older plans saved with the global switch on are converted back to the summer schedule on load. Per-day edits are stored as shown for that day. Do not reintroduce a manual switch unless asked.
- The lead PIN is in the page source. Do not print it in chat or in the UI.

- Calendar text (month, week, day and timeline) is one pixel larger than the original sizes, with the same layout. Keep that scale when adding new text.
